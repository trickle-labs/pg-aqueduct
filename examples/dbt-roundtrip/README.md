# dbt Round-Trip Example

This example demonstrates the `aqueduct ingest --from dbt-target` workflow: importing
compiled dbt stream-table models into an aqueduct migrations directory.

## What's here

```
dbt-project/          dbt project source (authors stream_table models)
  models/
    order_totals.sql           aggregate: sum of orders per customer
    promo_summary.sql          aggregate: promo-code redemption counts
    customer_ltv.sql           aggregate: customer lifetime value
  dbt_project.yml
  profiles.yml

target/               pre-compiled dbt target directory (output of `dbt compile`)
  manifest.json       model metadata, config, and dependency graph
  compiled/
    analytics/
      models/
        order_totals.sql
        promo_summary.sql
        customer_ltv.sql

migrations/           generated by `aqueduct ingest` (see workflow below)
  streams/
  sources/
```

## Workflow

### Step 1 — Compile the dbt project

In a real project you would run:

```bash
cd dbt-project
dbt compile --target prod
```

For this example the compiled output is already committed under `target/`.

### Step 2 — Ingest the compiled artefacts

```bash
aqueduct ingest \
  --from dbt-target \
  --target ./target \
  --project-dir .
```

This reads `target/manifest.json`, finds the three `stream_table` models, and generates:
- `migrations/streams/order_totals.sql`
- `migrations/streams/promo_summary.sql`
- `migrations/streams/customer_ltv.sql`
- `migrations/sources/raw_orders.sql`
- `migrations/sources/raw_promos.sql`

### Step 3 — Validate the generated files

```bash
aqueduct validate --project-dir .
```

### Step 4 — Plan the migration

```bash
aqueduct plan --to dev
```

Expected output: 3 CREATE stream-table steps, 0 rebuild steps.

### Step 5 — Apply the migration

```bash
aqueduct apply --to dev
```

### Step 6 — Simulate a column-add in a dbt model

Edit `dbt-project/models/order_totals.sql` to add a new column:

```sql
-- config(materialized='stream_table', schedule='30s', refresh_mode='DIFFERENTIAL')
SELECT
    customer_id,
    SUM(amount) AS total_amount,
    COUNT(*)    AS order_count   -- NEW column
FROM {{ source('warehouse', 'orders') }}
GROUP BY customer_id
```

Then re-compile and re-ingest:

```bash
cd dbt-project && dbt compile --target prod && cd ..
aqueduct ingest --from dbt-target --target ./target --project-dir .
aqueduct plan --to dev
```

Expected output: 1 IN-PLACE step (new aggregate column — no full rebuild needed).

### Step 7 — Apply and then rollback

```bash
aqueduct apply --to dev
aqueduct rollback --to dev
```

## Key takeaways

- dbt authors the SQL; `aqueduct` manages the migration lifecycle.
- `aqueduct ingest` is idempotent — running it again when nothing has changed writes
  nothing and exits cleanly.
- The generated migration files are canonical aqueduct format and can be edited
  directly once the team takes full ownership of the migrations directory.
- `aqueduct plan` uses its in-place classifier to avoid unnecessary full rebuilds:
  adding an aggregate column is an in-place migration, not a rebuild.
